The Problem

LLMs are isolated

  • Trained on a static snapshot of the world
  • No access to your files, database, or APIs
  • Cannot take actions or remember state between calls
  • Context window is the only "memory"
Every integration needs custom glue code — no standard protocol.

What we need

  • A standard way to give LLMs access to actions
  • A standard way to read external data
  • Reusable, versioned prompt templates
  • Works across models, hosts, and languages
→ Model Context Protocol

What is MCP?

MCP is an open protocol (Anthropic, Nov 2024) that standardises how LLM hosts connect to context sources and tool providers.

Open standard

JSON-RPC 2.0 over HTTP (Streamable), SSE, or stdio. Language-agnostic. Spec at modelcontextprotocol.io

Composable

One host can connect to many servers simultaneously. Mix tools from files, databases, APIs, and custom code.

Discoverable

Clients query tools/list, resources/list, and prompts/list at runtime — no hard-coded schemas.

"Think of MCP like a USB-C port for AI applications — a universal connector between LLM hosts and data / tool providers."

The Three Primitives

@mcp.tool

Actions the LLM can invoke.

  • Model-controlled
  • May have side effects
  • Input validated by JSON Schema
  • Returns structured results

Examples: run query, send email, calculate

@mcp.resource

Data the LLM can read.

  • Application-controlled
  • Identified by URI
  • Text or binary content
  • Static or parameterised (templates)

Examples: config, README, user profile

@mcp.prompt

Templates for the conversation.

  • User-controlled
  • Return message lists
  • Parameterised inputs
  • Bundle prompt engineering

Examples: code review, summarise, translate

Tools = actions  ·  Resources = context  ·  Prompts = templates

FastMCP

What is it?

  • Full MCP spec in one Python library
  • Decorator API — minimal boilerplate
  • Auto JSON Schema from type hints
  • Docstrings become descriptions
  • stdio (default), HTTP (Streamable), SSE
  • Built-in fastmcp dev inspector
The inspector runs the server over stdio and its own proxy — no second terminal. Open the printed URL (localhost:6274). 

from typing import Annotated
from fastmcp import FastMCP
from pydantic import Field

mcp = FastMCP("test_server")

@mcp.tool
def greet_person(name: Annotated[str, Field(
    min_length=1,
    description="Person's name, e.g. 'Ada Lovelace'.",
)]) -> str:
    """Return a short greeting for a person.

    Use for a direct greeting, not for email or notification delivery.
    Returns the greeting text and does not contact external services.
    """
    return f"Hello, {name}!"

if __name__ == "__main__":
    mcp.run()  # stdio by default

Descriptions Matter

The tool definition is the prompt the model reads

The model sees the name, description, and parameter schema — not your implementation. That text must explain whether, when, and how to call the tool.

What the model actually receives


{
  "name": "lookup_norwegian_postal_code",
  "description": "Look up a Norwegian postal
    code. Returns district name and
    municipality. Use for 4-digit NO codes
    only — not for foreign ZIP codes.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "code": {
        "type": "string",
        "pattern": "^[0-9]{4}$",
        "description": "4-digit Norwegian
          postal code, e.g. '5003'."
      }
    },
    "required": ["code"]
  }
}

Name + description + schema — that is the entire contract.

Why it changes the result

Selection

Vague text → wrong tool, or none.

Arguments

State legal values, units, and an example.

Boundaries

Say what it is not for.

Be precise, not verbose: descriptions are sent every turn.

from typing import Annotated, Literal
from pydantic import Field

@mcp.tool(
    annotations={"readOnlyHint": True},
)
def search_employee_directory(
    query: Annotated[str, Field(
        description="Free-text name or email "
        "fragment, e.g. 'yngve' or '@sonat.no'.",
    )],
    max_results: Annotated[int, Field(
        ge=1, le=50,
        description="Max rows to return (1-50).",
    )] = 10,
) -> list[dict]:
    """Search the internal employee directory
    by name or email.

    Use this to resolve a person's team, title
    or manager. Do NOT use it for customers or
    external contacts — see search_crm.

    Returns a list of objects with keys:
    name, email, team, title. Empty list means
    no match — do not retry with the same query.
    """
    ...

Name it like an API

verb_noun, specific and unambiguous. The name alone should narrow the choice.

Document the return shape

State the keys and what an empty or missing result means — that is what the model reasons over next.

Errors are instructions

raise ValueError("code must be 4 digits, got '5003x'") teaches a retry. "invalid input" teaches nothing.

Primitive 1 — Tools


from typing import Annotated, Literal
from fastmcp import FastMCP
from pydantic import Field

mcp = FastMCP("DemoServer")


@mcp.tool
def calculate(
  operation: Literal["add", "subtract", "multiply", "divide"],
  a: Annotated[float, Field(description="Left operand.")],
  b: Annotated[float, Field(description="Right operand.")],
) -> float:
    """Perform one arithmetic operation on two real numbers.

    Args:
        operation: One of add, subtract, multiply, or divide.
        a: Left operand; use ordinary decimal units.
        b: Right operand; must be non-zero for division.

    Returns:
        The numeric result as a JSON number. Raises a clear error for
        division by zero; do not retry division with the same denominator.
    """
    if operation == "add":      return a + b
    if operation == "subtract": return a - b
    if operation == "multiply": return a * b
    if operation == "divide":
        if b == 0:
            raise ValueError("Division by zero")
        return a / b
    raise ValueError(f"Unknown operation: {operation!r}")


@mcp.tool
def lookup_norwegian_postal_code(code: Annotated[str, Field(
    pattern=r"^[0-9]{4}$",
    description="4-digit Norwegian postal code, e.g. '5003'.",
)]) -> dict[str, str]:
    """Look up one Norwegian postal code in the bundled reference CSV.

    Use for Norwegian 4-digit postal codes only, not foreign ZIP codes.
    Returns the matching CSV row, including postal number, place, and
    municipality. Raises an error when the code is valid but not found.
    """
    import csv, pathlib
    path = pathlib.Path("reference_data/Postnummer_med_koordinater_utf8.csv")
    with path.open(encoding="utf-8") as f:
      for row in csv.DictReader(f, delimiter=","):
            if row.get("Postnummer") == code:
                return row
    raise ValueError(f"Postal code {code!r} not found")

Auto-generated schema

FastMCP reads the type hints to build the JSON Schema sent to the model — no manual schema writing needed.

Docstring = description

The docstring is surfaced to the model so it knows when and how to call the tool.

Errors surface safely

Raise ValueError or TypeError — FastMCP wraps them in a structured MCP error result the model can reason about.

Primitive 2 — Resources: Static


from fastmcp import FastMCP
from pathlib import Path
import time, datetime

mcp = FastMCP("DemoServer")


# ── Structured (JSON) resource ─────────────────────
@mcp.resource("data://config")
def get_config() -> dict:
    """Application configuration (read-only)."""
    return {
        "app_name": "MCP Demo",
        "version": "1.0",
        "supported_ops": ["add","subtract",
                          "multiply","divide"],
        "debug": False,
    }


# ── Plain text resource ────────────────────────────
@mcp.resource("data://readme")
def get_readme() -> str:
    """Return the project README as plain text."""
    return Path("README.md").read_text(encoding="utf-8")


# ── Runtime data resource ──────────────────────────
@mcp.resource("data://server-info")
def get_server_info() -> dict:
    """Current server runtime information."""
    return {
        "uptime_s": int(time.monotonic()),
        "now_utc": datetime.datetime.utcnow().isoformat(),
        "version": "1.0.0",
    }
URI scheme is freeform
Choose something meaningful to your domain: data:// file:// db:// api://

Return type → MIME type

  • str → text/plain
  • dict / list → application/json
  • bytes → blob

Discovery

resources/list enumerates all static resources.
resources/read fetches a specific URI.

Primitive 2 — Resources: Templates


import os, psycopg
from fastmcp import FastMCP
from pathlib import Path

mcp = FastMCP("DemoServer")
DB_URL = os.environ["DATABASE_URL"]


# ── Single-param URI template ──────────────────────
@mcp.resource("users://{user_id}/profile")
def get_user_profile(user_id: str) -> dict:
    """Fetch a developer profile by ID from PostgreSQL."""
    with psycopg.connect(DB_URL) as conn:
        row = conn.execute(
            "SELECT id, name, email, city "
            "FROM person WHERE id = %s",
            (user_id,),
        ).fetchone()
    if row is None:
        raise ValueError(f"User {user_id!r} not found")
    return {"id": row[0], "name": row[1],
            "email": row[2], "city": row[3]}


# ── Multi-param URI template ───────────────────────
@mcp.resource("files://{category}/{filename}")
def read_data_file(category: str, filename: str) -> str:
    """Read a file from the categorised data store."""
    base = Path("data").resolve()
    target = (base / category / filename).resolve()
    # Prevent path traversal
    if not target.is_relative_to(base):
        raise PermissionError("Path traversal denied")
    return target.read_text(encoding="utf-8")
URI templates (RFC 6570)
Curly-brace placeholders are extracted and passed as function arguments automatically.

Discovery

Template resources appear in resources/templates/list, not resources/list.

Security tip

Always sanitise URI parameters before using them in SQL queries or file paths — treat them like user input.

Primitive 2 — Resources: Files & Blobs


from fastmcp import FastMCP
from pathlib import Path

mcp = FastMCP("DemoServer")


# ── Markdown document ──────────────────────────────
@mcp.resource(
    "docs://guidelines",
    mime_type="text/markdown",
)
def get_guidelines() -> str:
    """Coding guidelines as Markdown."""
    return Path("docs/GUIDELINES.md").read_text(encoding="utf-8")


# ── CSV reference file ─────────────────────────────
@mcp.resource(
    "data://postnummer-csv",
    mime_type="text/csv",
)
def get_postnummer_csv() -> str:
    """Norwegian postal code reference (CSV)."""
    return Path(
    "reference_data/Postnummer_med_koordinater_utf8.csv"
    ).read_text(encoding="utf-8")


# ── Binary blob: PNG chart ─────────────────────────
@mcp.resource(
    "charts://activity",
    mime_type="image/png",
)
def get_activity_chart() -> bytes:
    """Daily activity as a PNG chart."""
    import io
    import matplotlib.pyplot as plt
    fig, ax = plt.subplots(figsize=(5, 3))
    ax.plot([3, 7, 2, 9, 4, 8, 5])
    ax.set_title("Daily Activity")
    ax.set_xlabel("Day")
    buf = io.BytesIO()
    fig.savefig(buf, format="png", bbox_inches="tight")
    plt.close(fig)
    return buf.getvalue()

Explicit MIME type

Pass mime_type= to tell clients how to handle the content. FastMCP sets text/plain or application/json by default.

Binary blobs

Return bytes with an image or binary MIME type. The MCP transport base64-encodes the payload automatically.

Vision-capable models can consume image blobs embedded directly in the conversation context.

Primitive 3 — Prompts


from fastmcp import FastMCP

mcp = FastMCP("DemoServer")


# ── Simple string prompt ───────────────────────────
@mcp.prompt
def summarise(text: str, max_words: int = 100) -> str:
    """Summarise text in at most max_words words."""
    return (
        f"Summarise the following text in at most "
        f"{max_words} words:\n\n{text}"
    )


# ── Multi-turn prompt ──────────────────────────────
@mcp.prompt
def code_review(
    code: str,
    language: str = "python",
) -> list:
    """Ask the model to review a code snippet."""
    return [
        {
            "role": "system",
            "content": (
                "You are an expert code reviewer. "
                "Be concise and constructive."
            ),
        },
        {
            "role": "user",
            "content": (
                f"Review this {language} code and "
                f"identify any issues:\n\n"
                f"```{language}\n{code}\n```"
            ),
        },
    ]


# ── Data analysis prompt ───────────────────────────
@mcp.prompt
def analyse_data(data: list[float]) -> str:
    """Ask the model to analyse a list of data points."""
    points = ", ".join(str(p) for p in data)
    return (
        f"Analyse these data points and identify trends, "
        f"outliers, and a brief summary:\n\n{points}"
    )

When to use prompts

Bundle prompt engineering expertise into a reusable, versioned template. Users pick a prompt; the host injects it into the conversation.

Return types

  • str → single user message
  • list[dict] → multi-turn thread

Protocol methods

Wiring It Together


# server.py
from fastmcp import FastMCP
from fastapi.middleware.cors import CORSMiddleware
from pathlib import Path
import uvicorn

mcp = FastMCP("DemoServer")


@mcp.tool
def add_integers(a: int, b: int) -> int:
  """Add two whole numbers and return their sum as a JSON integer."""
    return a + b


@mcp.tool
def greet_person(name: str) -> str:
  """Return a greeting for a person's name; does not send a message."""
    return f"Hello, {name}!"


@mcp.resource("data://config")
def get_config() -> dict:
  """Read-only demo configuration; returns version and debug settings."""
    return {"version": "1.0", "debug": False}


@mcp.resource("users://{user_id}/profile")
def get_user_profile(user_id: str) -> dict[str, str]:
  """Read a demo user profile by ID; returns id and display name."""
    return {"id": user_id, "name": f"User {user_id}"}


@mcp.prompt
def summarise(text: str) -> str:
  """Create a one-paragraph summary of the supplied text."""
    return f"Summarise in one paragraph:\n\n{text}"


if __name__ == "__main__":
    app = mcp.http_app(path="/mcp", transport="http")
    app.add_middleware(
        CORSMiddleware,
        allow_origins=["*"],
        allow_methods=["*"],
        allow_headers=["*"],
        expose_headers=["Mcp-Session-Id"],
    )
    uvicorn.run(app, host="127.0.0.1", port=8035)
Transport options
  • transport="http" — Streamable HTTP (recommended)
  • transport="sse" — HTTP + Server-Sent Events
  • mcp.run() — stdio (for CLI / subprocess)

CORS middleware

Must be added to the MCP sub-app directly. Middleware on a parent FastAPI app does not propagate.

MCP Server vs. Skill / Agent

MCP Server

Role: Capability Provider

  • Passive — waits for JSON-RPC calls
  • Exposes Tools, Resources, and Prompts
  • No reasoning or planning logic
  • Stateless; language-agnostic
  • Answers "what can be done?"
Examples: FastMCP server, DB connector,
file reader, external API wrapper

Skill / Agent

Role: Orchestrator

  • Active — drives the reasoning loop
  • Plans, acts, observes, and iterates
  • Decides which tool to call and when
  • Stateful across multiple steps
  • Answers "how do I achieve the goal?"
Examples: VS Code Copilot, Claude Desktop,
custom orchestration loops, LangChain / CrewAI agents

How they fit together

An Agent uses MCP Servers as its tool providers. The server exposes what is possible; the agent decides how and when to use those capabilities to reach a goal.

“MCP Server = the USB peripheral.
 Agent / Skill = the computer driving it.”

Current Adoption Status

The Shift to “Skills”

MCP Servers — Here to Stay

  • Enterprise growth: Millions of monthly downloads; backed by major firms via the Linux Foundation
  • Technical focus: Engineers drive most usage for backend, DevOps, and database tooling
  • Moving from early hype to practical, production use

The Rise of Agent Skills

  • Context bloat: Always-on servers consume too many tokens describing endless tools
  • Lighter alternatives: Developers increasingly use lightweight file-based “skills” or CLI tools instead of heavy local MCP setups
  • Coexistence: Most teams now layer both — skills to teach agents how to think, MCP for secure, standardised actions
Skills + MCP Servers are complementary, not competing. Skills define reasoning patterns; MCP Servers provide trusted capabilities.
